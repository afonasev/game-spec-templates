# Как подключить лабораторию геймдизайна

Заполненное описание подключения, игровые параметры и исключения хранятся в репозитории игры. OpenSpec не требуется.

1. Зафиксируйте версии `menu-base` и `design-lab`, а также точный commit шаблонов.
2. Укажите платформы, устройства, минимальные экраны, точки входа/возврата. По умолчанию вход во время матча отсутствует.
3. Определите редактируемые области, группировку и исключения. Выберите осмысленные параметры оформления; не добавляйте размещение объектов карты.
4. Заполните каталог метаданных и проверьте его согласованность с игровыми потребителями. Опишите сложные типы и связи.
5. Задайте ID Default, идентичность профиля/версии, правила копирования, переименования, удаления, нумерации и сохранения истории. Зафиксируйте порядок релизных версий.
6. Опишите доверенный dev-режим, пути Git-хранилища всех авторских профилей, версий и отметок, а также процесс их фиксации. Не выдавайте запись файла за commit.
7. Опишите сборку каталога всех отмеченных версий, защиту production-профилей и отдельное хранилище экспериментов игрока. Релизная отметка не запускает выпуск.
8. Подключите старт на последнем релизном Default, автоматическую активацию выбранной версии и действие возврата к Default. Сохранение черновика создаёт и активирует новую версию.
9. Опишите предупреждение с перечнем изменений перед любым действием, теряющим черновик, а также обработку ошибок записи и конфликтов.
10. Используйте последний релизный Default текущей поставки для новых отсутствующих полей; опишите поведение несовместимых версий. Проверьте обновление без удаления экспериментов.
11. Опишите путь теста выбранной версии. Если есть воспроизводимые сценарии, укажите seed и остальные условия.
12. Укажите только необходимые расширения: preview, live-применение, перенос данных и другие инструменты. Согласованные отклонения от применимых требований запишите отдельно.
13. Документируйте точную команду/URL тихого запуска и проверьте применимые [критерии](acceptance.md) минимально достаточным набором.

## Пример подключения

Числа, группы, пути и ID иллюстративные; они не становятся требованиями других игр.

```markdown
# Лаборатория условной игры

Пакеты: menu-base 0.1.0, design-lab 0.2.0.
Ревизия шаблонов: <точный commit>.
Платформы: Windows, macOS, web.
Устройства и размеры: <перечень и поддерживаемый диапазон>.
Вход: отдельное действие главного меню; возврат восстанавливает фокус.
Из матча и паузы лаборатория недоступна.

## Каталог

Группы: Юниты / Оружие / AI / Награды / Оформление.
Размещение объектов карты и технические инварианты исключены.

Ключ: combat.projectileEffect.
Группа: Юниты / Танк / Оформление.
Тип: перечисление готовых эффектов.
Название: Эффект снаряда.
Описание: меняет изображение; не меняет урон и коллизию.
Варианты: spark — Искра, plasma — Плазма.
Default: spark из последнего релизного Default новой поставки.
Применение: следующая игра из выбранной сохранённой версии.
Аналогичный контракт заполнен для каждого поля.

## Профили и поставка

Default ID: game-default, имя Default.
Новая версия получает max-known+1 внутри своего профиля.
Копирование конкретной версии создаёт новый ID и одну версию.
Dev-файлы: design/profiles/ и design/releases.json; все учитываются Git.
Процесс фиксации: <как авторская работа коммитится с веткой и хэшем>.
Способ доверенного dev-доступа: <механизм проекта>.

Поставка включает все и только отмеченные версии и их профили.
Production-профили пакета защищены на уровне данных.
Свои профили игрока: <путь устройства / browser storage key>.
Старт: последняя релизная версия game-default из проекта в dev, из пакета в production.
При смене профиля выбирается его последняя доступная версия.
Выбор сохранённой версии автоматически активирует её на сессию.
«Сбросить на релизную версию» возвращает Default без удаления истории.

## Черновик, ошибки и обновление

Предупреждение перечисляет поля «было → стало» и последствия.
Действия: «Продолжить редактирование» / «Сбросить изменения и перейти».
Запись: <механизм безопасного сохранения; конфликт writer при поддержке параллельных записей>.
Новые отсутствующие поля: defaults последнего релизного Default новой поставки.
Старые значения сохраняются; несовместимость объясняется без потери исходника.
При загрузке старые версии не переписываются; сохранение правок создаёт полную новую версию.

## Тест и расширения

«Запустить тест» открывает подготовку с выбранной сохранённой версией.
Состав и карта задаются в подготовке; профиль не перезаписывается.
Идентичность теста: профиль/версия.
Воспроизводимые сценарии: <не подключены или условия, включая seed>.
Preview: <не подключён или контракт>.
Live-применение, импорт/экспорт: не подключены.

## Тихая QA

Unity: <путь к executable> -noaudio -muted.
Web: <точный URL>/?muted=1; режим обработан до autoplay.
Wrapper передаёт параметры; сохранённые громкости не изменяются.

Отклонения: нет.
Приёмка: <проверенные сценарии, baseline, результаты и ожидающие платформы>.
```

## Проверка полноты

Описание должно позволять определить, какие данные редактируются, где сохраняются авторские и пользовательские версии, что входит в поставку, что активируется при запуске и как обновляется старый эксперимент. Новая ревизия общих шаблонов применяется отдельной задачей и не меняет подключённую игру автоматически.
