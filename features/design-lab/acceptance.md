## Доказательства и объём проверок

Фиксируются ревизии игры и шаблонов, состав конфигурации, dev/production режим, платформы, хранилище, устройства и поддерживаемые размеры экрана. Для сохранности профилей нужен сценарий обновления с данными предыдущей версии. Для предупреждения о потере черновика проверяются и отказ, и подтверждение. Контроль прав проверяется также через механизм данных.

Изолированные проверки допустимы для валидации, версий, миграций и отказов хранения; они не заменяют проверку влияния параметра в настоящем игровом пути. Визуальная компоновка требует просмотренных снимков; физические контроллеры и платформенные сценарии может проверить пользователь. Ожидающие результаты не объявляются пройденными.

Минимально достаточные проверки выбираются по diff, baseline, поведению и зависимостям. Полный регрессионный прогон не требуется автоматически и выполняется только по отдельной явной команде. Изменения в main считаются уже проверенными; full не является условием публикации. Сборка поставки и публикация требуют отдельного разрешённого scope. Для Unity Player-сборка нужна по команде человека либо как минимальная необходимая QA, когда затронутое поведение иначе не проверить; это не разрешает поставку.

Автоматические запуски выполняются без звука с самого старта: `-muted`, для Unity дополнительно `-noaudio`, для браузера `?muted=1` до autoplay. Wrapper передаёт режим приложению; сохранённые предпочтения и системная громкость не меняются. Поддержка раннего тихого старта проверяется целевым startup/audio-контрактом без слышимого вывода. Если тихий режим не позволяет выполнить проверку, фиксируется NotRun с причиной. Автоматическая аудиопроверка не разрешает слышимый вывод; человеческая аудиоприёмка остаётся отдельной.
