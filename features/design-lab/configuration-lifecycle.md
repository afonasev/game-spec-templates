# Профили и состав поставки

Версия: **0.2.0**. Это поясняющие таблица и пример; нормативный контракт находится в [requirements.md](requirements.md).

## Полномочия и источники данных

| Возможность | Dev-клиент автора | Production-клиент игрока |
|---|---|---|
| Источник профилей и релизных отметок | Актуальные файлы проекта, учитываемые Git | Неизменяемый каталог установленного пакета; свои профили отдельно |
| Выбор | Любая сохранённая версия проекта | Любая версия из пакета и своих профилей |
| Копирование конкретной версии | Новый профиль с одной начальной версией | То же |
| Редактирование и новые версии | Любой профиль, включая Default | Только свои профили |
| Переименование | Любой профиль, ID сохраняется | Только свои профили |
| Удаление | Дополнительные профили с подтверждением | Свои профили с подтверждением |
| Релизные отметки | Можно ставить и снимать у сохранённых валидных версий | Нельзя менять |
| Старт и сброс | Последний отмеченный Default из проекта | Последний релизный Default из пакета |

Удаление активного своего профиля возвращает к релизному Default. Защита черновика действует по LAB-DRAFT-02. Для dev-источника требуются доверенные полномочия; production нельзя переключить в dev изменением поля профиля.

## Пример

В проекте есть Default@1–3 и Experiment@1–2. Отмечены Default@1, Default@3 и Experiment@2.

- Пакет содержит Default@1, Default@3 и Experiment@2. Неотмеченные версии автоматически не включаются.
- При запуске выбран Default@3. Переключение на Experiment выбирает его последнюю доступную версию; можно вручную выбрать более старую, если она доступна.
- Копирование Default@1 создаёт новый профиль с одной версией и без релизных отметок.
- Если в dev снять отметку Default@3, следующий запуск dev и явный сброс выберут Default@1. Активный выбор текущей сессии сам не меняется.
- Установленный production продолжает использовать каталог своего пакета до установки нового выпуска.
- Если в обновлении добавлен параметр, старый эксперимент получает его значение из релизного Default новой поставки при загрузке. Сохранённые старые значения не меняются; редактирование и сохранение создают следующую полную версию.

Релизная отметка меняет будущий состав пакета. Git-фиксация, сборка и публикация выполняются процессом проекта и не запускаются самой отметкой.
